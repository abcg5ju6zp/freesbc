# S1: SIPp load generator and test driver

You prepare S1, build SIPp, and drive the FreeSBC load-test plan from here: S1 plays the carrier (`S1_PUBLIC_IP1`) and the phones and agents (`S1_PUBLIC_IP2`) against FreeSBC on `S2_PUBLIC_IP1`. Run this prompt **last**, after the operator confirms the S2 and S3 reports (`switches-up`).

## Lab (identical in the S1, S2 and S3 prompts)

Before pasting, replace every placeholder below (`S1_PUBLIC_IP1` … `S3_PRIVATE_IP`, the two passwords, `SIGNALWIRE_PAT`). If any value still looks like a placeholder, stop and ask the operator; do not guess addresses. Only the SignalWire token may be left empty.

All three hosts sit on one LAN. Each address has one job:

| Host | Address | Job | Must never carry |
|---|---|---|---|
| S1 (SIPp) | `S1_PUBLIC_IP1` | plays the **carrier**: listed in FreeSBC's `edge.carriers` | — |
| S1 | `S1_PUBLIC_IP2` | plays **phones and agents**: registers through FreeSBC, never a carrier source | — |
| S1 | `S1_PRIVATE_IP` | SSH / management only | any SIP or RTP |
| S2 (FreeSBC) | `S2_PUBLIC_IP1` | FreeSBC `public.ip` = `public.bind`: SIP 5060/udp + RTP 10000-59999/udp | SSH from the test |
| S2 | `S2_PUBLIC_IP2` | SSH / management only; FreeSBC never binds it | any SIP or RTP |
| S2 | `S2_PRIVATE_IP` | FreeSBC `private.ip`: the only path to the switches | anything from S1 |
| S3 (switches) | `S3_PRIVATE_IP` | FreeSWITCH 5060 (clients) / 5080 (carriers), Asterisk 5160; RTP 30000-39999 (FS), 40000-49999 (Asterisk) | anything not from `S2_PRIVATE_IP` |

Allowed flows: S1 public IPs ⇄ `S2_PUBLIC_IP1` (UDP); `S2_PRIVATE_IP` ⇄ `S3_PRIVATE_IP` (UDP, plus SSH S2 → S3); operator SSH to every host. **S1 must never reach S3**: in production the switch has no route to the internet side, and a test where it does measures the wrong thing.

Source of truth: `https://github.com/rasonyang/freesbc`, branch `load-test-harness`, directory `test/load/`. Read `test/load/README.md` before acting; it is the spec. If this prompt and the README disagree, stop and ask. FreeSBC under test: release **v0.2.0**.

## How to work

- You are root on this host only. Other hosts are other agents' business: when a step needs something there, print `CHECKPOINT <name>`, say exactly what the operator must do or confirm, and wait.
- Work under `/root/freesbc-lab/`. Append every command you run and its exit code to `/root/freesbc-lab/<host>.log`.
- Be idempotent: re-running a step must not break anything.
- Do not change SSH, netplan/interface addresses, the default route or an existing firewall without asking first. The sysctl and routing changes this prompt names are allowed; persist them only in the files named here.
- Fact first. When you report, separate what you measured from what you assume. Paste the command output that proves each claim.
- Finish with `/root/freesbc-lab/REPORT-<host>.md`: what was done, what was verified (with output), what failed, and open questions.

## Steps

### 1. Inventory and network checks (no changes yet)

- `ip -br -4 addr`, `ip route`, `nproc`, `free -g`, `lsb_release -a`.
- `S1_PUBLIC_IP1` and `S1_PUBLIC_IP2` must both be local. If either is not (1:1 NAT in front of S1), stop and ask: `SIPP_*_BIND` must then become the local addresses.
- `ip route get S2_PUBLIC_IP1 from S1_PUBLIC_IP1` and `… from S1_PUBLIC_IP2`: both must leave on the public NIC, never via `S1_PRIVATE_IP`.
- S1 must not reach S3: `ping -c 2 -W 1 S3_PRIVATE_IP` and `ip route get S3_PRIVATE_IP`. A reply means the S3 firewall is missing; report it (`CHECKPOINT isolation`) and do not start load until it is fixed.
- S1 must not reach FreeSBC's private side or its management address for SIP: nothing in this plan sends to `S2_PRIVATE_IP` or `S2_PUBLIC_IP2`.

### 2. Host settings

- `net.ipv4.conf.all.arp_ignore=1`, `net.ipv4.conf.all.arp_announce=2` in `/etc/sysctl.d/98-freesbc-lab-arp.conf` (one LAN: ARP answers only on the owning NIC, so S2's replies come back to the right address).
- After rendering (step 3): `cp out/sbc/99-freesbc-load.conf /etc/sysctl.d/ && sysctl --system`. The generator needs the same large default socket buffers as FreeSBC, or it drops its own received RTP and reports loss that is not FreeSBC's.
- Time sync active (`timedatectl`).

### 3. SIPp, tools, harness

Build SIPp exactly as README §4.4 (v3.7.9 from source with PCAP, SSL, GSL; `make sipp`), install to `/usr/local/bin/sipp`, then `sipp -v` must report `v3.7.9-TLS-PCAP`. Also install `tcpdump tshark sox gettext-base apache2-utils git sysstat`.

```sh
mkdir -p /root/freesbc-lab && cd /root/freesbc-lab
git clone --branch load-test-harness https://github.com/rasonyang/freesbc
cd freesbc/test/load   # write ./env from the block above, then:
./render.sh
cd out/sipp            # every test command below runs here, as root
```

Read `run.sh`, `rtp_report.sh` and the scenarios before the first run.

### 4. Pre-flight

1. `sipp S2_PUBLIC_IP1:5060 -sf scenarios/options.xml -key ua load-phone -i S1_PUBLIC_IP2 -bind_local -p 5098 -m 3 -nostdin`: 3 successful (FreeSBC answers public OPTIONS itself). Repeat with `-i S1_PUBLIC_IP1 -p 5097`.
2. `CHECKPOINT preflight-s2`: ask the operator to have the S2 agent confirm with `tcpdump` that this traffic arrived on S2's public NIC only.
3. Smoke T0 (the lab sequence, small): `./run.sh t1 CC=10 HOLD=5 SECS=10 CAPTURE=1 CAPTURE_DELAY=3 CAPTURE_SECS=6`, `./run.sh t2 CC=10 HOLD=5 SECS=10`, `./run.sh reg-a`, `./run.sh t3 CC=10 HOLD=5 SECS=10`, `./run.sh reg-b`, `./run.sh t4 CC=10 HOLD=5 SECS=10`, `./run.sh unreg-a`, `./run.sh unreg-b`. Every case must report 0 failed calls. Then `CHECKPOINT smoke-gauges`: the S2 agent reads the gauges; calls, dialogs, media sessions, ports in use and registrations must all be 0.
   If anything fails, stop. Collect `results/<run>/errors.log`, the S2 journal and the S3 switch log for the same minute, and report; do not work around a failure by changing scenarios or configs.

### 5. Test plan

Follow README §5 and §7. For each step record the SIPp summary, `rtp_report.txt` when captured, and ask the S2 agent for a latency sample at the middle of the step (`CHECKPOINT latency-<label>`; it runs `latency.sh <label> 30`).

Per switch (Asterisk first; then `CHECKPOINT switch-freeswitch` for the S2 agent to run `activate.sh freeswitch load`, and repeat; skip FreeSWITCH if S3 did not build it):

| Order | Command | Notes |
|---|---|---|
| 1 | `./run.sh ramp CASE=t1 STEPS="100 250 500 1000 1500 2000 3000" HOLD=60 STEP_SECS=300 COOL_SECS=90 CAPTURE=1` | concurrency, carrier → echo |
| 2 | `./run.sh ramp CASE=t2 STEPS="50 125 250 500 750 1000 1500" HOLD=60 STEP_SECS=300 COOL_SECS=90 CAPTURE=1` | hairpin: FreeSBC carries 2× |
| 3 | `./run.sh reg-a`, then `./run.sh ramp CASE=t3 STEPS="100 250 500 1000" HOLD=60 STEP_SECS=300 COOL_SECS=90 CAPTURE=1`, then `./run.sh unreg-a` | registered phones |
| 4 | `./run.sh reg-b`, then `./run.sh ramp CASE=t4 STEPS="50 125 250 500" HOLD=60 STEP_SECS=300 COOL_SECS=90 CAPTURE=1`, then `./run.sh unreg-b` | carrier → agent (the call-center shape) |
| 5 | `for c in 20 50 100 200 400 800; do ./run.sh t1 CPS=$c CC=$((c*6)) HOLD=5 SECS=120 LABEL=cps$c || break; sleep 60; done` | setup-rate limit |

T3/T4 steps cannot exceed the registered user counts (1000 each). Before each ramp, check S1 itself: run `mpstat 5` alongside; if S1 CPU passes 70 % or `nstat -az UdpRcvbufErrors` rises on S1, the step measured SIPp, not FreeSBC: stop the ramp and report it as generator-limited.

A ramp stops at the first step SIPp fails. Judge every step against README §7.1 using the SIPp results, the S2 collector CSV and the latency sample (ask the S2 and S3 agents for the rows covering the step's time window); the knee is the last step that passes every row, and the limiting signal is the first row that failed.

Then, once, on the current switch:

1. T5: `./run.sh t5 CPS=500 N_REG=1000`, then `./run.sh unreg-a`.
2. T6 under the load shield: `./run.sh reg-a`, `./run.sh t6-admission`, `./run.sh t6-ringcap` (expect exactly 64 answered, 36 × 503).
3. `CHECKPOINT shield-default` (S2: `activate.sh <switch> default`), then `./run.sh t6-rate CPS=100 T6_SECS=5`, `./run.sh t6-scanner`, `./run.sh t6-garbage COUNT=2000`; ask S2 for the drop counters before and after each. `CHECKPOINT shield-load` to restore, then `./run.sh unreg-a`.
4. T8 resilience (README §5.2) only with the operator present, one event at a time, each announced with a checkpoint.

Do not start the 24 h soak (T7) unless the operator asks.

### 6. Report

`REPORT-s1.md`, written as you go and finished at the end:

- environment: NIC map, SIPp version, sysctls, isolation check results;
- one table per case and switch: step, CC, CPS, offered/successful/failed calls, retransmissions, setup time p95, RTP loss and p99 jitter, FreeSBC SIP and RTP latency p99 (from S2), S2 CPU and `udp_rcvbuf_err` delta, S3 CPU, verdict;
- the knee per case and switch, with the limiting signal and which host it came from;
- T5/T6/T8 outcomes against the expectations written in `run.sh` and the README;
- every anomaly, with the result directory that shows it.

Numbers in the report must come from files under `results/` or from the other agents' outputs; nothing is estimated.
