# S2: FreeSBC

You prepare S2 and run FreeSBC v0.2.0 for a three-server load test. S2 is the only host that touches both sides: SIPp traffic arrives on `S2_PUBLIC_IP1`, the switches are reached through `S2_PRIVATE_IP`. Run this prompt **first**.

## Lab (identical in the S1, S2 and S3 prompts)

Before pasting, replace every placeholder below (`S1_PUBLIC_IP1` … `S3_PRIVATE_IP`, the two passwords, `SIGNALWIRE_PAT`). If any value still looks like a placeholder, stop and ask the operator; do not guess addresses. Only the SignalWire token may be left empty.

All three hosts sit on one LAN. Each address has one job:

| Host | Address | Job | Must never carry |
|---|---|---|---|
| S1 (SIPp) | `S1_PUBLIC_IP1` | plays the **carrier**: listed in FreeSBC's `edge.carriers` | — |
| S1 | `S1_PUBLIC_IP2` | plays **phones and agents**: registers through FreeSBC, never a carrier source | — |
| S1 | `S1_PRIVATE_IP` | SSH / management only | any SIP or RTP |
| S2 (FreeSBC) | `S2_PUBLIC_IP1` | FreeSBC `public.ip` = `public.bind`: SIP 5060/udp + RTP 10000-59999/udp | SSH from the test |
| S2 | `S2_PUBLIC_IP2` | SSH / management only; FreeSBC never binds it | any SIP or RTP |
| S2 | `S2_PRIVATE_IP` | FreeSBC `private.ip`: the only path to the switches | anything from S1 |
| S3 (switches) | `S3_PRIVATE_IP` | FreeSWITCH 5060 (clients) / 5080 (carriers), Asterisk 5160; RTP 30000-39999 (FS), 40000-49999 (Asterisk) | anything not from `S2_PRIVATE_IP` |

Allowed flows: S1 public IPs ⇄ `S2_PUBLIC_IP1` (UDP); `S2_PRIVATE_IP` ⇄ `S3_PRIVATE_IP` (UDP, plus SSH S2 → S3); operator SSH to every host. **S1 must never reach S3**: in production the switch has no route to the internet side, and a test where it does measures the wrong thing.

## How to work

- You are root on this host only. Other hosts are other agents' business: when a step needs something there, print `CHECKPOINT <name>`, say exactly what the operator must do or confirm, and wait.
- Work under `/root/freesbc-lab/`. Append every command you run and its exit code to `/root/freesbc-lab/<host>.log`.
- Be idempotent: re-running a step must not break anything.
- Do not change SSH, netplan/interface addresses, the default route or an existing firewall without asking first. The sysctl and routing changes this prompt names are allowed; persist them only in the files named here.

## Steps

### 1. Inventory (no changes)

- `ip -br -4 addr`, `ip route`, `ip rule`, `uname -r`, `lsb_release -a`, `nproc`, `free -g`, `ethtool -l <nic>` for each NIC.
- Confirm all three S2 addresses are local. Record which NIC owns `S2_PUBLIC_IP1`, `S2_PUBLIC_IP2` and `S2_PRIVATE_IP`. If `S2_PUBLIC_IP1` and `S2_PRIVATE_IP` share one NIC, say so in the report: it is the README's degraded topology T-B (works, but the planes are no longer separated by interface).
- `systemctl is-active docker ufw firewalld nftables`, `nft list ruleset | head -50`, `lsmod | grep -E 'nf_conntrack|nf_nat_sip'`.
- If Docker is running on S2, stop and ask: its iptables NAT rules make the kernel conntrack every FreeSBC UDP flow, which the test must not pay for.

### 2. Network hygiene (same-LAN specifics)

All NICs share one LAN, so two things can silently break FreeSBC:

1. **ARP flux.** Linux answers ARP for any local address on any NIC by default, so S3 may learn the *public* NIC's MAC for `S2_PRIVATE_IP`. FreeSBC's private socket has a BPF ingress filter that accepts only datagrams arriving on the NIC that owns `private.ip`; switch traffic arriving on the public NIC is dropped with no log, only upstream timeouts. Set, and persist in `/etc/sysctl.d/98-freesbc-lab-arp.conf`:
   `net.ipv4.conf.all.arp_ignore=1`, `net.ipv4.conf.all.arp_announce=2` (and the same per NIC).
2. **Return path.** Check:
   - `ip route get S3_PRIVATE_IP from S2_PRIVATE_IP` → must leave on the private NIC;
   - `ip route get S1_PUBLIC_IP1 from S2_PUBLIC_IP1` and `… S1_PUBLIC_IP2 from S2_PUBLIC_IP1` → must leave on the NIC that owns `S2_PUBLIC_IP1`.
   If either is wrong, propose a source policy route (`ip rule add from S2_PUBLIC_IP1 table 101` plus the matching `ip route … table 101`), apply it only after the operator agrees, and show the `ip route get` output again.

Also: unload `nf_conntrack_sip` / `nf_nat_sip` if loaded; make sure chrony (or systemd-timesyncd) is synchronized (`chronyc tracking` or `timedatectl`).

`tinyproxy` is installed but stays stopped (`systemctl disable --now tinyproxy`) unless step 5 needs it.

### 4. Install FreeSBC v0.2.0

Follow README §4.2 exactly: release archive with SHA256 check, the shipped `freesbc.service`, the drop-in `out/sbc/freesbc-load.conf` as `/etc/systemd/system/freesbc.service.d/load.conf`, `out/sbc/99-freesbc-load.conf` into `/etc/sysctl.d/`, `/etc/freesbc` as `root:freesbc 0750`. Then:

```sh
cd /root/freesbc-lab/freesbc/test/load/out/sbc
./activate.sh asterisk load      # Asterisk first: it is the switch the harness has verified
systemctl enable freesbc
```

Verify, and paste the output:

- `journalctl -u freesbc -n 30` shows `edge proxy listening` with `carrier_sources=S1_PUBLIC_IP1/32` and `switch_nodes=S3_PRIVATE_IP:5160`, and no error.
- `ss -lunp | grep freesbc`: bound to `S2_PUBLIC_IP1:5060` and `S2_PRIVATE_IP:5060` only; never `0.0.0.0`, never `S2_PUBLIC_IP2`.
- `curl -s -u admin:CHANGE_ME_ADMIN http://127.0.0.1:8080/metrics | grep -E '^freesbc_(active|media_ports)'`.
- `sysctl net.core.rmem_default net.core.wmem_default net.ipv4.ip_local_port_range net.ipv4.conf.all.arp_ignore`.
- `systemctl show freesbc -p LimitNOFILE` = 1048576.

### 5. Internet for S3 (only if S3 has none)

`CHECKPOINT s3-internet`: ask the operator whether S3 can reach the internet (the S3 agent tests it). If not, give S3 a temporary forward proxy, user space only (no NAT and no `ip_forward`, so no conntrack load on S2):

- `/etc/tinyproxy/tinyproxy.conf`: `Listen S2_PRIVATE_IP`, `Port 3128`, `Allow S3_PRIVATE_IP`, no other `Allow`; `systemctl restart tinyproxy`;
- tell the operator: S3 uses `http://S2_PRIVATE_IP:3128`;
- when the operator reports that S3 is finished (`CHECKPOINT s3-done`), run `systemctl disable --now tinyproxy` and confirm with `ss -ltnp | grep 3128` (empty).

### 6. After S3 is up

`CHECKPOINT switches-up`: wait for the operator to confirm the S3 report. Then:

- `tcpdump -ni <private-nic> -c 20 host S3_PRIVATE_IP` while the S1 agent runs its OPTIONS pre-flight: switch traffic must appear on the private NIC (never on the public one; check that too with `tcpdump -ni <public-nic> host S3_PRIVATE_IP`, which must stay silent).
- Start the collector for the whole test session and leave it running:
  `nohup ./collect.sh /root/freesbc-lab/results/sbc-$(date +%s).csv 5 >/dev/null 2>&1 &`
- Write `/root/freesbc-lab/latency.sh <label> <secs>`: captures both NICs at once (`tcpdump -s 0 -B 65536 … udp`), then runs `./sbc_latency.py pub.pcap priv.pcap --sip-ports 5060,5080,5160` and saves everything under `/root/freesbc-lab/results/latency-<label>/`. Test it for 5 s.

### 7. Serving the test

The S1 agent drives the test plan. When the operator relays a request from it, run exactly one of:

| Request | Command (in `out/sbc`) |
|---|---|
| use Asterisk / FreeSWITCH, load shield | `./activate.sh asterisk load` / `./activate.sh freeswitch load` (restart) |
| production shield for T6 | `./activate.sh <current switch> default` (hot reload: confirm `config reloaded` in the journal) |
| latency sample | `/root/freesbc-lab/latency.sh <label> 30` |
| gauges | `curl -s -u admin:… http://127.0.0.1:8080/metrics \| grep -E '^freesbc_(active\|media_ports_in_use\|edge_sessions\|edge_invite_rejects\|shield_drops\|edge_admission\|sip_parse_failures\|media_port_allocation\|sip_handler_panics)'` |

If the operator installs S1's SSH public key here (`/root/.ssh/authorized_keys`, reached via `S2_PUBLIC_IP2` only), S1 may run these itself; you do not set that up unasked.

Never restart FreeSBC during a step unless asked: it drops every call and registration.
