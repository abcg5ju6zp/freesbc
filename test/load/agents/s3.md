# S3: switches (FreeSWITCH + Asterisk)

You prepare S3 and run FreeSWITCH and Asterisk side by side, in Docker with host networking, as the backend switches behind FreeSBC. S3 is private-only: everything it serves is reached through FreeSBC on `S2_PRIVATE_IP`. Run this prompt **after** the S2 agent has finished its steps 1-4.

## Lab (identical in the S1, S2 and S3 prompts)

Before pasting, replace every placeholder below (`S1_PUBLIC_IP1` … `S3_PRIVATE_IP`, the two passwords, `SIGNALWIRE_PAT`). If any value still looks like a placeholder, stop and ask the operator; do not guess addresses. Only the SignalWire token may be left empty.

All three hosts sit on one LAN. Each address has one job:

| Host | Address | Job | Must never carry |
|---|---|---|---|
| S1 (SIPp) | `S1_PUBLIC_IP1` | plays the **carrier**: listed in FreeSBC's `edge.carriers` | — |
| S1 | `S1_PUBLIC_IP2` | plays **phones and agents**: registers through FreeSBC, never a carrier source | — |
| S1 | `S1_PRIVATE_IP` | SSH / management only | any SIP or RTP |
| S2 (FreeSBC) | `S2_PUBLIC_IP1` | FreeSBC `public.ip` = `public.bind`: SIP 5060/udp + RTP 10000-59999/udp | SSH from the test |
| S2 | `S2_PUBLIC_IP2` | SSH / management only; FreeSBC never binds it | any SIP or RTP |
| S2 | `S2_PRIVATE_IP` | FreeSBC `private.ip`: the only path to the switches | anything from S1 |
| S3 (switches) | `S3_PRIVATE_IP` | FreeSWITCH 5060 (clients) / 5080 (carriers), Asterisk 5160; RTP 30000-39999 (FS), 40000-49999 (Asterisk) | anything not from `S2_PRIVATE_IP` |

Allowed flows: S1 public IPs ⇄ `S2_PUBLIC_IP1` (UDP); `S2_PRIVATE_IP` ⇄ `S3_PRIVATE_IP` (UDP, plus SSH S2 → S3); operator SSH to every host. **S1 must never reach S3**: in production the switch has no route to the internet side, and a test where it does measures the wrong thing.

Source of truth: `https://github.com/rasonyang/freesbc`, branch `load-test-harness`, directory `test/load/`. Read `test/load/README.md` before acting; it is the spec. If this prompt and the README disagree, stop and ask. FreeSBC under test: release **v0.2.0**.

## How to work

- You are root on this host only. Other hosts are other agents' business: when a step needs something there, print `CHECKPOINT <name>`, say exactly what the operator must do or confirm, and wait.
- Work under `/root/freesbc-lab/`. Append every command you run and its exit code to `/root/freesbc-lab/<host>.log`.
- Be idempotent: re-running a step must not break anything.
- Do not change SSH, netplan/interface addresses, the default route or an existing firewall without asking first. The sysctl and routing changes this prompt names are allowed; persist them only in the files named here.
- Fact first. When you report, separate what you measured from what you assume. Paste the command output that proves each claim.
- Finish with `/root/freesbc-lab/REPORT-<host>.md`: what was done, what was verified (with output), what failed, and open questions.

## Steps

### 1. Inventory (no changes)

- `ip -br -4 addr`, `ip route`, `lsb_release -a` (expected Ubuntu 24.04; say so if not), `nproc`, `free -g`, `docker --version`, `nft list ruleset | head -50`.
- Confirm `S3_PRIVATE_IP` is local. `ip route get S2_PRIVATE_IP` must use the NIC that owns it.
- Internet: `curl -sS -m 5 -o /dev/null -w '%{http_code}\n' https://github.com`. If it fails, `CHECKPOINT need-proxy`: ask the operator to have the S2 agent start its temporary proxy (S2 step 5), then use `http://S2_PRIVATE_IP:3128` for apt (`/etc/apt/apt.conf.d/95lab-proxy`), for git/curl (`https_proxy`/`http_proxy` in the shell only), and for dockerd (`/etc/systemd/system/docker.service.d/lab-proxy.conf` with `HTTP_PROXY`/`HTTPS_PROXY`, then `systemctl daemon-reload && systemctl restart docker`). Note every proxy setting you add; step 6 removes them.

### 2. Host settings

- `net.ipv4.conf.all.arp_ignore=1`, `net.ipv4.conf.all.arp_announce=2` in `/etc/sysctl.d/98-freesbc-lab-arp.conf` (one LAN: answer ARP only on the NIC that owns the address).
- `net.core.rmem_default=1048576`, `net.core.wmem_default=1048576`, `net.core.rmem_max=16777216`, `net.core.wmem_max=16777216` in `/etc/sysctl.d/99-freesbc-lab.conf`.
- Time sync must be active (`timedatectl`).

### 3. Firewall: only FreeSBC reaches the switches

Add one nftables table, `inet freesbc_lab`, in `/etc/nftables.d/freesbc-lab.nft` (or a file the nftables service loads), without touching existing tables:

- `raw`-priority prerouting/output chains: `notrack` for UDP from/to `S2_PRIVATE_IP` (the RTP flows must not fill conntrack);
- input chain, `policy accept` (do not lock the operator out):
  - accept `iif lo`, `ct state established,related`;
  - accept UDP from `S2_PRIVATE_IP` to 5060, 5080, 5160, 30000-39999, 40000-49999;
  - **drop everything from `S1_PRIVATE_IP`, `S1_PUBLIC_IP1`, `S1_PUBLIC_IP2`**;
  - drop UDP to 5060, 5080, 5160, 30000-49999 from any other source.
Show `nft list table inet freesbc_lab`. Ask before changing the policy to drop or touching SSH rules.

### 4. Harness and images

```sh
apt-get update && apt-get install -y git curl docker.io docker-compose-v2 gettext-base apache2-utils sox tcpdump
mkdir -p /root/freesbc-lab && cd /root/freesbc-lab
git clone --branch load-test-harness https://github.com/rasonyang/freesbc
cd freesbc/test/load   # write ./env from the block above, then:
./render.sh && cd out/switch
```

Read `docker-compose.yml`, both Dockerfiles, `install-freeswitch.sh` and `install-asterisk.sh` before building. Then:

- Asterisk: `docker compose build asterisk` (pass `--build-arg http_proxy=… --build-arg https_proxy=…` if step 1 needed the proxy).
- FreeSWITCH, only if the SignalWire token in the lab section is not empty: `printf %s 'SIGNALWIRE_PAT' > signalwire_token && chmod 600 signalwire_token`, `docker compose build freeswitch` (same proxy args). The token reaches the build as a secret, not a layer; delete `signalwire_token` after the build.
- `docker compose up -d` (only the services you built).

If a build fails, stop and report the error; do not edit the harness files to make it pass. A fix belongs in the repo, through the operator.

### 5. Verify (paste every output)

Asterisk:
- `docker exec asterisk asterisk -rx 'pjsip show transports'` → `S3_PRIVATE_IP:5160` udp;
- `… 'pjsip show endpoints' | tail -1` → `Objects found: 2001` (2000 users + `loadcarrier`); `… 'pjsip show endpoint loadcarrier'` shows `Match: X-FreeSBC-Carrier: loadcarrier` and `outbound_proxy : sip:S2_PRIVATE_IP:5060;lr`;
- `… 'dialplan show from-carrier'` and `'dialplan show from-client'` list `_80X.`, `_81X.`, `_82X.`, `7100`, `7101`.

FreeSWITCH (if built):
- `docker exec freeswitch fs_cli -x 'sofia status'` → profiles `internal` on `S3_PRIVATE_IP:5060`, `external` on `S3_PRIVATE_IP:5080`, gateway `loadcarrier` (NOREG);
- `fs_cli -x 'sofia status gateway loadcarrier'` → its proxy is `S1_PUBLIC_IP1:5070` and its outbound proxy `S2_PRIVATE_IP:5060`;
- `fs_cli -x 'status'` → `20000 session(s) max` and a per-second maximum of 2000 (stock: 1000 / 30);
- `fs_cli -x 'list_users user 10000'` and `… 'list_users user 20999'` → one user each;
- the startup log has no STUN lookup and no `mod_signalwire`.

Both: `ss -lunp` shows the switches on `S3_PRIVATE_IP` (not on any other address for 5060/5080/5160); `docker exec <name> sh -c 'ulimit -n'` is 1048576 in each container.

These configs are verified for Asterisk; **FreeSWITCH's have never been loaded by a real FreeSWITCH before this run**, so treat any FreeSWITCH warning as a finding and report it verbatim.

### 6. Hand-off

- Remove every proxy setting from step 1 (apt file, docker drop-in, then `systemctl daemon-reload && systemctl restart docker && docker compose up -d`), and `CHECKPOINT s3-done` so the S2 agent stops its proxy.
- `CHECKPOINT switches-up`: tell the operator the switches are ready, with the step 5 outputs.

### 7. During the test

- Start and leave running: `nohup ./collect.sh /root/freesbc-lab/results/switch-$(date +%s).csv 5 >/dev/null 2>&1 &` (in `out/switch`).
- On request: `docker restart asterisk|freeswitch` (T8), `docker logs --since 5m <name>`, `fs_cli -x 'show calls count'`, `asterisk -rx 'core show channels count'`.
- Watch for the switch becoming the bottleneck: CPU above 70 %, FreeSWITCH `sessions-per-second`/`max-sessions` messages, Asterisk taskprocessor warnings. Report them with timestamps; they make a step's result the switch's limit, not FreeSBC's.

### 8. Report

`REPORT-s3.md`: OS, image versions (`docker exec asterisk asterisk -V`, `fs_cli -x version`), firewall table, verification outputs, whether FreeSWITCH was built, every warning seen, and the collector file path.
